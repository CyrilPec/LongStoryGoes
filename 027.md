027 — Construction Evolution Experiment
Purpose

Experiment 027 extends LongStoryGoes from a world that can simulate individual physical actions into a world that can search for physical constructions.

The central question is:

Can an experiment discover a construction that survives a specified load, while the World remains the authority over what physically happened?

The first experiment uses:

wooden plank
steel nails
hammer impact
gravity
load
material properties
numerical calculations
PyBullet
NumPy

The experiment is intentionally small and CPU-friendly.

Architectural Principle

The most important rule is:

Experiment proposes
        ↓
World validates
        ↓
Physics calculates consequences
        ↓
World records the accepted result
        ↓
Experiment measures the result


The experiment must not directly modify authoritative world state.

An AI should not be allowed to say:

joint.strength = 100


and then declare success.

Instead it should request an action through the World.

The World decides whether that action is legal and what consequence occurs.

Important Limitation

The current physical model is not a real engineering model.

In particular, the current joint-capacity calculation in 027+01.py is deliberately simple.

It is an experimental hypothesis.

Do not present its result as proof that a real-world nail joint would safely support the same load.

The purpose of 027 is partly to discover where the current model is inadequate.

Tensor Direction

NumPy is sufficient for the current experiment.

A future tensor backend may use:

NumPy
PyTorch
another numerical backend


but the World should not depend on a GPU.

The system should work on CPU.

The user's computer includes an NVIDIA GTX 750 Ti, so GPU-dependent modern machine-learning infrastructure should not become a requirement.

Tensors should first be used for things that naturally benefit from vectorized numerical representation:

positions
velocities
forces
rotations
material vectors
many candidate designs
repeated experiments

A tensor does not automatically make a model more physically correct.

Evolution Principle

The goal is not to make increasingly complicated code.

The goal is to make the World increasingly capable of answering:

"Did this action actually work?"

and:

"Why did it work or fail?"

Eventually an AI should be able to propose:

wood + nails + hammer


then discover:

better nail spacing


then:

different plank dimensions


then:

different materials


then perhaps discover an entirely different construction.

The AI proposes.

The World tests.

The result becomes persistent knowledge.

Long-Term Goal

The larger LongStoryGoes idea is that future AI sessions can continue from previous experiments.

A future AI should be able to:

Read the World model.
Read previous experiment results.
Identify weaknesses.
Create a new experiment.
Run it.
Compare results.
Improve the World when justified.
Leave a new experiment and results for the next AI.

Rule for Future Changes

Do not change an authoritative World rule merely because an AI thinks a different rule would be better.

First create an experiment demonstrating the problem.

Then compare:

old World model
vs.
new World model


If the new model performs better against reproducible tests, document why it should replace the old one.

The World should evolve through evidence.

Definition of Success for 027

027 is successful if it produces a reproducible experiment in which:

candidate constructions can be generated automatically
candidates are evaluated through the World
successful and failed candidates are recorded
results can be reproduced from a known seed
another AI can understand the experiment
another AI can continue the experiment
the physical model can be challenged and improved

A successful experiment is not necessarily one where every candidate works.

Failure is valuable data.
