# 032+03 — Machining Model Research Handoff

## Project idea

We are developing a modular computational model of machining,
starting with turning and eventually extending toward milling.

The central idea is:

    geometry
        ↓
    material engagement
        ↓
    removed area / chip geometry
        ↓
    cutting force
        ↓
    torque / power / tool loading
        ↓
    dynamic simulation
        ↓
    later: stress / temperature / field models

The intention is NOT to immediately reproduce a huge commercial
machining simulator.

Instead, the model is built progressively, with each layer being
testable and replaceable.

---

# Current conceptual architecture

The project treats machining as a transformation problem.

Instead of trying to calculate everything simultaneously:

    CAD + material + tool + speed + feed
                  ↓
            enormous physics model

we construct:

    geometric model
          ↓
    engagement model
          ↓
    force model
          ↓
    mechanical model
          ↓
    field model

Each level can be validated before moving to the next.

# Existing files

## 032.py

First simplified turning model.

Basic relationship:

    Fc = Kc * A

where:

    Fc = cutting force [N]
    Kc = specific cutting coefficient [N/mm²]
    A  = engagement/chip area [mm²]

Also calculates:

    RPM
    torque
    cutting power
    tool bending moment
    tool bending stress

This establishes the basic geometry → force → mechanics chain.

---

# 032+01.py

Geometry-derived version.

Instead of manually assuming:

    A = ap * f

the workpiece is represented as a graph:

    R(z)

and material removal changes the graph.

The removed profile area is calculated numerically:

    A = ∫ ΔR(z) dz

The chain becomes:

    workpiece graph
          ↓
    material removal
          ↓
    removed area
          ↓
    cutting force

This establishes that the cutting area can originate from
geometry rather than being manually entered.

Important:

This area is currently a simplified profile-plane engagement
area, NOT a complete 3D chip cross-section.

# 032+02.py

PyBullet integration.

Architecture:

    geometry
        ↓
    engagement area
        ↓
    cutting force
        ↓
    force vector
        ↓
    PyBullet

PyBullet is used for rigid-body mechanics and visualization.

It is NOT being used as the metal plasticity solver.

The machining model calculates the force.

PyBullet receives the force and shows its mechanical effect.

Current force components:

    Ft = tangential force
    Fr = radial force
    Fa = axial force

Initial simplified assumptions:

    Fr = 0.30 * Fc
    Fa = 0.10 * Fc

These are placeholders and should eventually be replaced by
tool-geometry/material-dependent relations.

PyBullet visualization:

    RED   = tangential force
    GREEN = radial force
    BLUE  = axial force

# 032+03.py

Current model.

This introduces the Kienzle/Victor cutting-force formulation.

Instead of:

    Fc = Kc * A

we use:

    Fc = b * kc1_1 * h^(1-mc)

where:

    b      = uncut chip width [mm]
    h      = uncut chip thickness [mm]
    kc1_1  = specific cutting force at h = 1 mm [N/mm²]
    mc     = material exponent

Equivalent specific cutting force:

    kc = kc1_1 * h^(-mc)

For the simplified turning approximation:

    b = depth of cut
    h = feed per revolution

therefore:

    Fc = ap * kc1_1 * f^(1-mc)

---

# Why Kienzle is important

The constant-Kc model is useful as a first approximation, but
real cutting force changes with chip thickness.

The Kienzle relation introduces this dependency:

    kc(h) = kc1_1 * h^(-mc)

Therefore the model can capture nonlinear force behavior as
feed/chip thickness changes.

This is an established machining model, not a newly invented
equation.

---

# 032+03 validation approach

The file contains an example AISI 1040 turning benchmark dataset.

The model fits:

    kc1_1
    mc

from the benchmark data using logarithmic linearization.

Starting equation:

    Fc = b * kc1_1 * h^(1-mc)

Divide by b:

    Fc / b = kc1_1 * h^(1-mc)

Take logarithm:

    ln(Fc/b)
        =
    ln(kc1_1) + (1-mc) ln(h)

Define:

    x = ln(h)
    y = ln(Fc/b)

Then:

    y = A + Bx

so:

    kc1_1 = exp(A)

and:

    mc = 1-B

# Validation metrics

032+03.py calculates:

    MAE
    MAPE
    RMSE
    R²
    maximum percentage error

Definitions:

    MAE
        mean absolute force error

    MAPE
        mean absolute percentage error

    RMSE
        root mean square error

    R²
        coefficient of determination

These allow quantitative comparison between models.

---

# VERY IMPORTANT VALIDATION LIMITATION

The current 032+03.py fits the Kienzle coefficients using the
same benchmark data that it subsequently evaluates.

Therefore this is:

    model fitting + internal consistency check

It is NOT yet independent predictive validation.

For proper research validation, we should eventually do:

    training experiments
            ↓
        fit kc1_1, mc
            ↓
    completely independent experiments
            ↓
        prediction
            ↓
        error metrics

Better still:

    experimental dataset
          /       \
      training    test
         ↓          ↓
       fit       prediction
                    ↓
                 error

# Scientific research direction

The goal is not necessarily to create the most complicated
machining simulation.

The goal is to investigate whether a machining model can be
constructed progressively from simpler validated layers.

Possible hierarchy:

## Level 1 — empirical force

    Fc = Kc A

## Level 2 — Kienzle

    Fc = b kc1_1 h^(1-mc)

## Level 3 — speed-dependent model

Include:

    Vc

in the cutting-force relation.

For example, conceptually:

    kc = f(h, Vc, material, tool)

The exact formulation should be determined from literature
and/or experimental data rather than invented.

## Level 4 — actual tool geometry

Instead of:

    b = ap
    h = f

calculate actual local engagement from tool geometry.

## Level 5 — spatial force distribution

Instead of one force:

    Fc

use local force density:

    dF/dA

and integrate:

    F = ∫_A q(x,y,z) dA

## Level 6 — field model

Eventually represent quantities as fields:

    force field
    stress field
    temperature field
    velocity field
    deformation field

Then mathematical operators such as:

    gradient
    divergence
    curl

may become useful.

This is a later stage, NOT something that should be added before
the basic force model is validated.

---

# Important distinction about PyBullet

PyBullet is useful for:

    rigid-body motion
    collision detection
    force application
    constraints
    joints
    tool/workpiece dynamics
    visualization

It is NOT a complete metal-cutting FEM solver.

For realistic chip formation, one would eventually need more
advanced methods such as:

    FEM / FEA
    material constitutive models
    plasticity
    friction
    thermal coupling
    damage/fracture
    remeshing or other large-deformation techniques

Therefore the intended architecture is:

    machining physics model
              ↓
        force/contact data
              ↓
          PyBullet
              ↓
        machine/tool dynamics

rather than trying to make PyBullet itself calculate metal
plastic deformation.

# Potential research contribution

A possible master's-level topic:

"Development of a computational model for prediction of cutting
forces during turning based on geometric engagement."

Possible research workflow:

    1. Develop geometric workpiece representation.
    2. Calculate engagement.
    3. Calculate cutting force.
    4. Implement Kienzle model.
    5. Validate against published data.
    6. Perform own cutting experiments.
    7. Fit model coefficients.
    8. Test on independent experiments.
    9. Connect force model to dynamic simulation.
    10. Quantify computational cost vs prediction accuracy.

For PhD/aspirant-level work, a stronger contribution could be
the progressive transition:

    geometric model
          ↓
    empirical force model
          ↓
    local force model
          ↓
    field representation
          ↓
    coupled thermo-mechanical model

The scientific novelty would need to be established through
literature review and comparison with existing approaches.

Do NOT claim that the project has invented a new cutting-force
theory without a literature review.

# Current research principle

The main principle is:

    Do not add complexity before validating the current layer.

For example:

    constant Kc
        ↓
    validate
        ↓
    Kienzle
        ↓
    validate
        ↓
    speed dependence
        ↓
    validate
        ↓
    actual geometry
        ↓
    validate
        ↓
    spatial field model

This prevents the project from becoming an untestable collection
of assumptions.

# Core idea to preserve

The project is based on the observation that a difficult
machining problem can become manageable after a suitable
transformation.

Instead of calculating everything at once:

    complicated machining process

we construct:

    geometry
        →
    area/contact
        →
    force
        →
    mechanics
        →
    fields

The complexity is moved into well-defined interfaces.

The eventual goal is a reusable Python library where different
physical models can be plugged into the same geometry/dynamics
framework.

Possible future API concept:

    Workpiece
    Cutter
    Material
    Engagement
    ForceModel
    Tool
    Machine
    Simulation
    Validator

The current scripts are prototypes for that architecture.
They are not yet a finished library.
